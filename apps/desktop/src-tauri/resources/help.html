Begin with a conversation

Orchestrix opens at Home each time. Your projects and conversations remain in Sessions on the right. New session prepares a conversation; the first nonempty message creates its record. A project may exist without conversations. Use the compact chat-plus beside a project to start inside it, or attach an existing conversation through the composer’s + menu.

Messages record your intent. This build prepares manual structured tasks rather than producing autonomous planning responses.

Prepare and authorize a task

  1. Open Connections and select Subscription, then bind the validated Codex executable and its existing authenticated home. Recheck reads official metadata without inference. Saving configuration does not create a login or independent account vault.
  2. Create or select a project and send your objective. Choose Prepare task.
  3. Select the repository and a separate worktree destination through native dialogs. Add concrete acceptance criteria, authorized context files and any checks you want to run. Every check has its own executable, arguments and time limit.
  4. Inspect the preparation and the requested policy. Resume new admissions if they are suspended.
  5. Explicitly authorize the runtime turn and the listed checks, then submit. Sending a chat message alone never grants command execution.

Inspect an exact result, then request review

Studio exposes durable worker status, the immutable artifact, check evidence and review findings. Historical evidence is labeled separately from current verification. Request independent review only after a verified artifact exists. The reviewer has a distinct session and enforced read-only permissions. Invalid output, quota failure, timeout and protocol errors never count as approval or rejection.

A valid rejection can be corrected within the recorded budget after explicit authorization. The correction stays on the same Task, preserves provenance, reruns checks and needs a new review. Reviewed work still awaits final integration; this build does not apply it to your destination.

Use the supporting editor

File → Open file grants one file; Open folder grants a tree. New file requires a granted destination and never overwrites an existing file. Files opened here do not automatically enter agent context, including .env files.

Edit text and code, use Markdown preview, undo with Ctrl+Z and save with Ctrl+S. A dot marks unsaved changes. Closing a changed file offers Save, Discard or Cancel. A denied save preserves your buffer. If disk contents changed, saving reports a conflict instead of silently overwriting the other version. Immutable artifact inspection cannot edit historical evidence.

Keep control of execution

Suspending new work prevents new admissions; it does not pause an active turn. Cancel applies to the work owned by Orchestrix. Closing the window either continues execution or suspends future admissions according to Settings. It never indiscriminately shuts down the daemon.

Reconnect uses snapshots and event cursors. A lost reply retains the original command identity for inspection; it does not start another execution. Recovery status and deterministic inspection remain available without model quota. Missing ownership evidence requires explicit inspection and may block further work.

Make the workspace yours

Settings stays in a floating window and closes when you click outside. English is the default; Português and Español are available. Studio is the default theme, Compact the default density, and text scale ranges from 80% to 200%.

Files, Studio and Connections share one movable Navigation panel. Sessions is independent. Drag a panel header to the left or right, use its position menu, or use left/right arrow keys on the header. Panels on the same side become tabs. Resize the separators until a side collapses; the activity rail always remains available. Reorder activities by dragging or Alt+Up/Down.

Resource strategies and requested model/reasoning preferences affect future decisions. Effective settings require observed confirmation. Subscription Only never falls back to paid APIs. Quota that the runtime does not expose is shown as Not reported.

Windows is the current validation target. API execution adapters, provider OAuth, multiple independent account vaults, autonomous planning and final integration retain their own development gates.
